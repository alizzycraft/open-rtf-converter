# Fuzz Targets

These targets are for `cargo fuzz` and intentionally live outside the main crate. The fuzz crate depends on `open-rtf-converter` with `default-features = false` so the harness exercises the memory-only core without pulling in the CLI wrapper.

Useful runs:

```powershell
cargo fuzz run rtf_lexer
cargo fuzz run rtf_parser
cargo fuzz run rtf_to_pdf_passive
```

Before an architecture or release commit, compile every target and run this bounded smoke procedure (requires `cargo-fuzz`):

```powershell
cargo check --manifest-path fuzz/Cargo.toml --all-targets
cargo +nightly fuzz run rtf_lexer -- -runs=100
cargo +nightly fuzz run rtf_parser -- -runs=100
cargo +nightly fuzz run rtf_to_pdf_passive -- -runs=100
```

The fixed run count keeps the smoke gate bounded. CI runs it on Ubuntu with nightly because libFuzzer sanitizer coverage is not supported by this repository's pinned stable Windows MSVC toolchain. On every platform, fuzz-target compilation and the deterministic mutation regression remain required. Longer time-based campaigns are scheduled/manual and should retain any minimized crash corpus in the matching `fuzz/corpus` directory.

The `rtf_to_pdf_passive` target treats every successful conversion as a security assertion: the generated bytes must pass the passive PDF audit.
